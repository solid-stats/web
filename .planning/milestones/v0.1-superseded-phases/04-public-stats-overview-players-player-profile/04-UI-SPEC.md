# Phase 4 — UI Design Contract

> Visual and interaction contract for the Phase 4 public-stats trio: Stats Overview, Players list,
> Player profile, and the shared public-stats shell/state/trust layer. Generated by
> gsd-ui-researcher for gsd-planner and gsd-executor.
>
> **Scope note.** This is a v0.1 design milestone phase: deliver durable Ladle surface prototypes in
> `packages/design`, not TanStack Start routes, real API wiring, server pagination, SSR loaders, or
> real TanStack Table/Virtual integration. Future app contracts are documented where they affect the
> visual model, but Phase 4 implementation stays fixture-driven.
>
> **Pre-populated from upstream.** Sources: `04-CONTEXT.md` D-01..D-07, `04-RESEARCH.md`,
> `ROADMAP.md` Phase 4 success criteria, `REQUIREMENTS.md` SURF-01..03 and QUAL-01..06,
> `03-UI-SPEC.md`, `DESIGN.md`, `packages/design/src/styles/theme.css`, `.design/CLAUDE.md`, and the
> existing `packages/design/src/shared/uikit/**` primitives.

## Surface List

| Surface | Job | Primary User Task | Must Reuse |
|---------|-----|-------------------|------------|
| Shared public-stats shell/state/trust layer | One shell, loading model, tier system, provenance/freshness layer, RU/EN copy, and fixture graph shared by all three surfaces | Move between overview, list, and profile without semantic drift | `AppShell`, `AsyncBoundary`, `FreshnessPill`, `ProvenanceLine`, shared fixtures, shared i18n keys |
| Stats Overview | Dense entry point into public stats with top leaderboards, stat tiles, microcharts, and links into deeper stats areas | Inspect leaders and choose a public stats area | `StatTile`, `MiniStatGrid`, `Sparkline`, `AutoTable`, `CompactList`, `Button`/`Link`, trust layer |
| Players list | Search/filterable, period-aware player leaderboard with tier-colored Score and K/D | Find a player, compare rank, change period, open profile | `Select`, `AutoTable`, `CompactList`, `TierChip`/`Pips`, `AsyncBoundary`, trust layer |

Shared active nav state: Overview uses stats/home section; Players list and Player profile use
`activeKey="players"` so the list and profile read as one public-stats flow.

## Spacing Scale

Declared values use Tailwind's stock 4px scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | icon-label gaps, pip gaps, compact metadata |
| sm | 8px | dense row inner gaps, compact card gaps |
| md | 16px | default section/card padding, form/filter control gaps |
| lg | 24px | surface section padding, table/header separation |
| xl | 32px | major stacked-section separation |
| 2xl | 48px | large overview/profile region breaks only |
| 3xl | 64px | rare page-level top/bottom spacing; avoid inside dense data panels |

Exceptions: 44px minimum interactive target (`min-h-11`) for buttons, links, tabs, sort triggers,
select triggers, show-more controls, provenance explanation control, and clickable rows. Table and
skeleton geometry may use computed pixel widths/heights only for colgroups, row heights, spacer rows,
and reserved viewports; those are layout geometry, not theme tokens.

## Typography

Phase 4 uses exactly four type sizes and two weights in surface-specific composition. Existing UIKIT
primitives may keep their already approved internal roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Dense table/meta | 13px | 400 | 1.35 |
| Label / column header | 12px | 600 | 1.5 |
| Section heading | 22px | 600 | 1.25 |

Hero stat readouts consume the existing `StatTile` role from UIKIT (`stat-xl`, Exo 2, tabular,
48px/64px depending on the primitive state). Do not introduce new text steps for this phase.
All numeric columns and stat values use tabular numerals and right alignment where tabular comparison
matters. Russian labels that become long must stack label-over-value before shrinking below 12px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-0` `#0A0D13`, `bg-1` `#0F131C` | page backdrop, shell, sticky bars |
| Secondary (30%) | `surface-1` `#151A25`, `surface-2` `#1B212F`, `surface-3` `#232B3B` | panels, tables, inputs, hover/active row surfaces |
| Accent (10%) | `primary` `#36C5E0` | reserved elements listed below |
| Destructive | `loss` `#FF5C6C` | system error actions and future destructive flows only; no destructive product action ships in Phase 4 |
| Semantic | `win`, `loss`, `warn`, `info` with `-weak` and `-border` | outcome, delta, unknown/conflict/stale/info states; never color-alone |

Accent reserved for: focus rings, links, provenance "How it's computed", primary CTAs, active nav,
active tabs, selected/active select options, selected row inset marker, sparkline primary stroke,
and Score/K/D tier affordances when the UIKIT tier primitive prescribes it. Do not tint whole rows
cyan to imply "synced"; rows are uniform unless selected/focused.

Tier color contract: Score and K/D tier cells combine color with pips and level/threshold text.
Other player metrics stay neutral mono. Unknown/conflict values render as literal `Unknown`/`Conflict`
badges, not `0`, dash-only, or color-only marks.

## Shared Mock Graph And Invariants

One Phase 4 fixture graph is mandatory. It extends/reuses
`packages/design/src/shared/uikit/_fixtures/roster.ts` and `tiers.ts`; it must not import
`.design/hifi/*`.

| Invariant | Contract |
|-----------|----------|
| Single source | Overview, Players list, Player profile, stories, and tests read from one Phase 4 fixture module |
| Score formula | `Score = (kills - TK) / (games + deaths-from-TK)` via existing `scoreOf` |
| K/D formula | `K/D = (kills - TK) / (deaths + deaths-from-TK)` via existing `kdOf` |
| Tier derivation | `tierFor(metric, value, SS_BASELINE, period)` with explicit `period`; no hardcoded cutoffs |
| Ranking | Vasiliy remains #1 in Overview, Players list, and Player profile hero context |
| Tail | Generated tail descends to negative Score/K-D and never outranks seeded Overview leaders |
| Periods | Rotation typical/few/many/heavy and all-time warm/cold/in-session states are represented |
| Trust | Every surface has replay count, freshness, and provenance; unsupported per-player coverage/conflict panel is not built |
| Consistency | A player's rank, Score, K/D, tier, squad, sparkline, bounty, and freshness agree across the three surfaces |

Fixture volumes:

| State | Required Data Shape |
|-------|---------------------|
| Empty | zero rows or no matching filters; not a loading state |
| Few | 3-5 rows; proves compact copy and no orphan/air issues |
| Many | rotation: hundreds represented by visible window + spacers; all-time: ~2040 represented by fixture metadata + visual window |
| Limit-reached | enough rows to show capped desktop window and mobile top-N show-more with accurate remaining count |

## Shared Loading And Trust Layer

| Situation | Visual Contract |
|-----------|-----------------|
| Rotation default | Instant ready state; no skeleton; freshness/provenance visible |
| All-time deep link, cache warm | Instant ready state; no skeleton; freshness pill explains cached aggregate |
| All-time deep link, cache cold | Shell/header/filter area render immediately; table/stat content uses skeleton matching final geometry; label says aggregate is recomputing |
| In-session switch to all-time | Short skeleton around the affected table/content only; no shell/nav shift |
| Offline/reconnecting/stale | `DataTrustBanner` or `FreshnessPill` state near the affected content; no focus steal; no row reorder above viewport |
| System error | `ErrorState` with request/debug id and retry/contact path |
| Empty/onboarding | `EmptyState` with next action; no fake zero values |

CLS contract: loading skeletons match final table colgroup, header, row height, stat tile height, and
section reserved height. `loading` and `ready` boxes must be byte-for-byte equal for content that can
swap asynchronously. Empty/error states may use their own honest reserved min-height, but they must
not appear as accidental layout collapse.

## Stats Overview Contract

Priority order:
1. Page identity and freshness/provenance.
2. Hero public stats summary and leader highlights.
3. Top players leaderboard with Score/K/D tier cues and sparkline.
4. Entry sections to Players, Squads, Rotations, Commander, and Bounty.
5. Secondary trust/status notes.

Layout:

| Width | Contract |
|-------|----------|
| 360 | One column; no horizontal scroll; top leaderboards become compact top-N lists; entry points stack; microcharts stay fixed-height and legible |
| 768 | One or two naturally equal stat rows; tables still avoid horizontal scroll; labels can wrap label-over-value |
| 1024 | Desktop nav may still be collapsed by container; overview sections remain stacked; no cramped sidebars |
| 1280 | Desktop table/leaderboard cards may use capped scroll-in-card; entry grid can use 2-3 equal cards |
| 1920 | Data container uses available width up to 1760; no narrow 1240-style guttered layout |
| 2560 | Container caps and centers; width becomes more columns/rows inside the cap, not stretched tables |
| Ultrawide 3440+ | Main content remains capped at 1760 and centered; no table exceeds readable ceiling |

Scenario endings x5:

| Ending | Required Rendering |
|--------|--------------------|
| Success | Overview leaderboards and entry points render from the shared fixture graph; Vasiliy #1; freshness/provenance visible |
| System error | ErrorState inside the content region with retry/contact and `{id}`; shell remains usable |
| Loading | Only aggregate-dependent cards skeletonize; shell and headings are present; skeletons reserve final card/table height |
| Onboarding | "No public stats yet" style state for a new deployment; entry points remain visible but disabled/informational as appropriate |
| Empty | No rows for selected filters; actionable clear-filter/change-period copy |

Data-volume states x4:

| Volume | Required Rendering |
|--------|--------------------|
| Empty | EmptyState in each affected leaderboard area; no zeroed leaders |
| Few | Cards/tables remain balanced; no stretched empty strip |
| Many | Desktop capped scroll window with sticky header and count caption; mobile top-N list |
| Limit-reached | Count caption names total; show-more/entry link communicates that more exists |

Interactions: overview entry cards/links have 44px target, visible focus, descriptive labels, and
keyboard activation. Microcharts include a text summary or accessible figure label; chart color is
not the only signal.

## Players List Contract

Priority order:
1. H1/list identity, freshness/provenance, and period selector.
2. Search/filter controls.
3. Player leaderboard with Score and K/D tier cues.
4. Mobile show-more or desktop virtual-window affordance.
5. Trust/loading/empty/error state.

Controls:

| Control | Contract |
|---------|----------|
| Search | Search input with visible label or accessible label; query state is story-controlled in Phase 4 and URL-owned in v1.0 |
| Filters | Filter chips/selects must be resettable and keyboard-operable; no filter state stored in UIKIT primitives |
| Period selector | Single `Select`; default = active rotation; options include active rotation and all-time; no "last 4 weeks" option |
| Sort | Table sort triggers use existing `Th`; no real engine, but visual state and labels are present |
| Row open | Whole row/primary link opens player profile; focus and hover are visually distinct |

Desktop vs mobile:

| Width | Contract |
|-------|----------|
| 360 | `CompactList`; top-N default 20 or fewer in visible demo; show-more `{n}`; no nested scroll; no horizontal scroll |
| 768 | Compact/list hybrid allowed; keep core metrics visible: player, games, kills, TK, deaths, K/D, Score when room permits |
| 1024 | Boundary width must not overflow; if desktop table is not yet safe, stay compact |
| 1280 | `AutoTable` desktop capped scroll-in-card with sticky header, fixed colgroup, visual spacer rows |
| 1920 | Comfortable density table; trend/microchart can widen; no extra density toggle |
| 2560 | Same capped container; table must not stretch beyond readable ceiling |
| Ultrawide 3440+ | Container cap check; table remains inside 1760px content |

Scenario endings x5:

| Ending | Required Rendering |
|--------|--------------------|
| Success | Active rotation renders instantly with rows, tiers, and trust layer |
| System error | ErrorState with id/retry/contact; filter controls retain their visible state |
| Loading | All-time cold/in-session skeleton matches table/compact geometry; rotation does not skeletonize |
| Onboarding | New deployment/no parsed players copy; period selector visible |
| Empty | Search/filter no-match state with clear-filter action and total count context |

Data-volume states x4:

| Volume | Required Rendering |
|--------|--------------------|
| Empty | EmptyState; no table with fake zero row |
| Few | 3-5 rows; no stray bottom air; desktop viewport still reserves its designed height only when demonstrating the table window |
| Many | Desktop visual virtualization contract: fixed viewport, sticky header, spacer rows; mobile top-N |
| Limit-reached | All-time ~2040 metadata; mobile show-more does not dump the full list; desktop count caption communicates total |

Loading model:

| Period / Cache | Required State |
|----------------|----------------|
| active rotation | ready immediately |
| all-time warm | ready immediately |
| all-time cold | cold aggregate skeleton with recompute copy |
| all-time in-session switch | short skeleton around table/list only |

Column priority: Player -> Games -> Kills -> TK -> Deaths -> K/D -> Score. Score and K/D are
tier-colored with pips; all other columns are neutral mono. Tablet keeps columns when they fit; do
not drop data prematurely.

## Player Profile Contract

Priority order:
1. Identity: current nick, sg.zone link, squad/status, freshness/provenance.
2. Hero Score and K/D tiles.
3. Mini-stat grid: games, kills, TK, deaths, deaths-from-TK, bounty.
4. Rotation/bounty/history/replay tabs.
5. Nick history and replay/history details.

Layout: full-width stacked sections only. Do not create two mismatched-height columns. Side-by-side
is allowed only for naturally equal tiles, such as Score/K/D hero tiles or paired tables with fixed
row slots. Headline data stays high; do not bury Score/K/D or provenance below history.

Breakpoint behavior:

| Width | Contract |
|-------|----------|
| 360 | Identity stacks; Score/K/D may stack or use two equal tiles if readable; tabs scroll/fit without horizontal page scroll; tables become compact top-N sections |
| 768 | Hero tiles can sit side-by-side; nick history remains stacked below; no empty side rail |
| 1024 | Sections remain full-width; tab panels use table/list pattern appropriate to available container |
| 1280 | Rotation/replay tab tables use capped desktop table window when useful |
| 1920 | Main content uses 1760px data container; headline area stays compact and high |
| 2560 | Container caps and centers; no stretched profile line lengths |
| Ultrawide 3440+ | Same cap; profile does not become a three-column dashboard |

Scenario endings x5:

| Ending | Required Rendering |
|--------|--------------------|
| Success | Vasiliy profile shows fixture-consistent rank, hero stats, squad/status, tabs, provenance, freshness |
| System error | Profile content error with id/retry/contact; shell and breadcrumb/back affordance remain |
| Loading | Profile skeleton reserves identity, hero stat, and tab/table geometry; no CLS on final swap |
| Onboarding | Public profile exists but has no included replays yet; copy explains when stats appear |
| Empty | Empty tab panel states for nick history/replays/bounty with actionable/contextual copy |

Data-volume states x4:

| Volume | Required Rendering |
|--------|--------------------|
| Empty | EmptyState per tab/panel; unknown values are badges, not blanks |
| Few | 1-3 nick/history/replay rows without trailing-gap bug |
| Many | Desktop capped scroll-in-card with sticky header and count caption; mobile top-N |
| Limit-reached | Count captions and show-more affordance; no mobile nested scroll |

Profile details:
- Nick equals sg.zone profile slug and links to `https://sg.zone/profile/<nick>` as an external link
  affordance in the story.
- SteamID, if present in future copy, is masked to last four only.
- Pending identity/merge state is a quiet inline row inside the identity/history section, not a large
  trust banner.
- No canonical/SO badge, no full-width commander strip, no separate bounty card that competes with
  Score/K/D; bounty is a mini-stat unless the active Bounty tab explains it.

Tabs: Rotation, Bounty, History, Replays. Keyboard roving and focus are owned by `Tabs`; active tab is
not color-only. Each tab panel has its own state/data-volume story coverage.

## Interaction And Accessibility Contract

| Area | Contract |
|------|----------|
| Keyboard | Every control reachable and operable by keyboard: nav, search, select, sort headers, row links, tabs, show-more, provenance explanation |
| Focus | Visible focus ring on every interactive control; focus not hidden under sticky header/nav; route/story state changes do not steal focus |
| Target size | Interactive targets >=44x44 CSS px |
| Color semantics | Never color-alone; tier/freshness/outcome/trust states pair color with label, icon, pips, or marker |
| Tables | Caption/accessible name present; sort state announced; numeric cells tabular and right-aligned |
| Charts | Sparkline/microchart has accessible text summary and fixed height; no chart-only meaning |
| Loading | Loading state announced politely where asynchronous; skeleton is aria-hidden if decorative |
| Errors | User errors live by fields; system errors carry id + recovery/contact |
| Motion | Transform/opacity only; `prefers-reduced-motion` respected |
| Mobile | No nested scroll, no horizontal scroll, no hover-only meaning |

Use WCAG 2.2 AA plus the project-targeted AAA checks from the design-review skill: 44px enhanced
targets, enhanced focus appearance, focus not obscured, keyboard no exception, section headings,
location/breadcrumb context where applicable, no timing, no auto context change.
