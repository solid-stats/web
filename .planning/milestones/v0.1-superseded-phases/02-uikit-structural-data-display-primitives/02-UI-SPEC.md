## Spacing Scale

The system uses **Tailwind's STOCK 4px scale** — no custom keys (DESIGN.md "Layout"; `styling.md`). The generic GSD "8-point only" heuristic does NOT apply; the established 4px grid is authoritative. Dense defaults: **8 / 12 / 16 dominate; 24 / 32 separate major regions.**

| Token (Tailwind) | Value | Usage in this phase |
|------------------|-------|---------------------|
| `p-0.5` | 2px | hairline insets, chip inner gap |
| `p-1` | 4px | icon↔label gap, pip gap |
| `p-2` | 8px | compact cell padding, badge inner padding |
| `p-3` | 12px | comfortable cell padding, nav item padding |
| `p-4` | 16px | card padding, stat-tile padding, section gap |
| `p-6` | 24px | region separation inside a card |
| `p-8` | 32px | major region break |

**Exceptions (per this phase):**
- Table row height is fixed by density, NOT padding: `ROW_H` comfortable **52px** / compact **44px** (D-01) — a fixed-height row model so the virtualization-ready spacer math and CLS = 0 hold.
- Touch targets ≥ **44×44px** (QUAL-03 / WCAG 2.5.5): `MobileTabBar` items 44px, icon-only controls 44px even when the visual glyph is 16–20px (pad the hit area). `--nav-h` = 56px, `--tabbar-h` = 60px (DESIGN.md `layout`).

## Typography

Documented FROM `DESIGN.md typography` (full 11-step scale `2xs`→`5xl`, 4 weights, 4 line-heights) → theme.css L64-99. The generic "3–4 sizes / 2 weights" heuristic does NOT apply — this is an established system. Below is the curated **role subset** each Phase-2 family consumes; apply via the `typography.roles.*` recipes (DESIGN.md L115-190), never by re-inventing sizes.

| Role | Family | Size | Weight | Line-height | Tracking | Used by |
|------|--------|------|--------|-------------|----------|---------|
| `overline` | mono | 11px (`2xs`) | 500 medium | 1.5 | caps 0.12em, uppercase | provenance meta, micro labels |
| `label` | body | 12px (`xs`) | 600 semibold | 1.5 | label 0.06em, uppercase | table headers, stat-tile labels, nav labels |
| `body` | body | 14px (`base`) | 400 regular | 1.5 | normal | default UI text, empty/error body |
| `body-sm` | body | 13px (`sm`) | (regular) | 1.35 dense | normal | dense table body, mobile compact rows |
| `caption` | body | 12px (`xs`) | (regular) | 1.5 | normal | placeholder, disabled, decorative captions only |
| `h3` | display (Exo 2) | 22px (`xl`) | 600 semibold | 1.25 snug | snug −0.01em | section / banner / empty-state headings |
| `h4` | body | 18px (`lg`) | 600 semibold | 1.25 snug | normal | card titles |
| `stat` | mono (tabular) | 13px (`sm`) | 500 medium | — | — | numeric table cells, mini-stat values, pips labels |
| `stat-xl` | display (Exo 2, tabular) | 48px (`4xl`) | 700 bold | 1.08 tight | tight −0.02em | hero Score / K/D tiles |

## Component Inventory & Per-Family Contracts

Each component is its own PascalCase slice at `packages/design/src/shared/uikit/<Component>/` (`index.ts` + colocated `*.stories.tsx`), graduated through `packages/design/src/index.ts` (D-02; `architecture.md` slice rules). `shared/uikit` = generic primitives only, props-down, no imports of pages/business/localization. Every story demonstrates the **7 component states** (enabled / hover / pressed / focused / selected / disabled / loading), the **×4 data-volume** states for any list/table/field, and the **×5 scenario endings** where applicable; defines the **click zone** (whole row beats text); is axe-clean, keyboard-operable, ≥44px targets, never color-alone (D-08).

> The exact Ladle 5.1 state-demonstration mechanism and the axe/keyboard verification harness are **research items for the planner** — see "Claude's Discretion / Research items" below. They are NOT contract blockers.

### KIT-01 — Nav shell

**Slices:** `AppShell` (skip-link → header → `main`/landmarks → mobile tab-bar; role-aware slots) · `NavBar` (desktop top nav, `--nav-h` 56px, active section, cyan accent) · `MobileTabBar` (bottom tabs, `--tabbar-h` 60px, 44px targets) · `SkipLink`.

- **Roles ×4:** `AppShell`/`NavBar` accept a role-aware `slots`/`items` prop; signed-out shows public sections + a login slot; player adds "My requests"; moderator adds "Queue"; admin adds "Admin". Phase 2 ships the slot mechanism + visual states, NOT auth wiring (no RBAC, no routes — v1.0). Denied items are simply absent from the passed item list.
- **States ×7:** nav item enabled / hover (`surface-1` bg, `text-primary`) / pressed (`surface-2`, `translateY(1px)`) / focused (`--shadow-ring`) / selected = active section (cyan text + cyan underline/edge marker, never color-alone — also `aria-current="page"`) / disabled (`text-subtle`, 0.6) / loading (n/a for nav — skip).
- **Click zone:** whole nav item (icon + label), not just the text.
- **Landmarks (QUAL-03 / WCAG 2.4.10):** `SkipLink` → `<header>` `<nav aria-label>` → `<main id>` → mobile `<nav aria-label="…">`. One meaningful `<h1>` is the page's responsibility, not the shell.
- **Responsiveness:** desktop top nav `≥ md` (768px); below `md` the top nav collapses and `MobileTabBar` is the primary nav. Keyed off the **container** (`@container`), not viewport. No horizontal scroll. Backdrop-blur on sticky nav/tab-bar is allowed (DESIGN.md Elevation); never blur content.
- **Icons:** Lucide, 18–20px in nav.

### KIT-02 — Data-table family

**Slices:** `Table` · sortable `Th` · `TableRow` · `DensityToggle` · `CompactRow` (mobile) · `Pagination` / `CursorAffordance`. Recipes: `table-header` / `table-row` / `table-row-zebra` / `table-cell-numeric` (DESIGN.md L370-391). **Presentational-only (D-01):** NO `@tanstack/react-table`, NO `@tanstack/react-virtual`. The table demonstrates the full VISUAL contract as markup + tokens + fixture rows passed as props.

- **Visual contract (what graduates):** sticky-header scroll-in-card (`table-header` on `surface-2`, `position: sticky`, `borderBottom border-1`); `colgroup` with fixed column widths; **reserved scroll height → CLS = 0**; virtualization-ready row model = fixed `ROW_H` (52/44) + spacer rows above/below the visible window; cursor/pagination affordances rendered but inert (no server).
- **Sortable `Th`:** plain `<button>` inside the `<th>` (no overlay/menu), Lucide arrow (`arrow-up`/`arrow-down`/none), `aria-sort="ascending|descending|none"`; sort state is a controlled prop (parent owns it — no engine).
- **`DensityToggle`:** container class switching `ROW_H` (Nano-store-shaped in v1.0; here a controlled prop / story arg). Comfortable 52 / Compact 44.
- **Selected row:** `primary-weak` fill + inset `2px 0 0 primary` left-edge marker (not fill-only) + `aria-selected`.
- **States ×7 (row):** enabled (`surface-1`) / hover (`surface-3`) / pressed / focused (ring, not hidden under sticky header — WCAG 2.4.12) / selected (above) / disabled / loading (skeleton row, exact colgroup/height).
- **Click zone:** **whole row** is the click target (beats the player-name text).
- **Data-volume ×4:** empty (EmptyState, actionable copy + total count) / few (table holds, no orphan layout) / many (capped window + sticky scroll on desktop; total in caption e.g. `по убийствам · 200`) / limit-reached (cursor affordance shows end-of-list, no more pages).
- **Scenario endings ×5:** success (rows) / system-error (ErrorState with ref id + contact) / user-error (n/a — read-only) / loading (skeleton matching final colgroup+header+row dims) / onboarding+empty (empty-but-expectant + empty).
- **Responsiveness (QUAL-02, container-keyed):** desktop = scroll-in-card with sticky header; **mobile (`< md`)** = `CompactRow` layout — top-N + "показать ещё · N" expander, secondary columns dropped (e.g. max-dist), **NO horizontal scroll, NO nested scroll** (page already scrolls). Tablet (`lg`) keeps every column when there's room. Verify at the real 360px floor.
- **Numeric cells:** `table-cell-numeric` — tabular mono, right-aligned, signed deltas.

### KIT-03 — Stat primitives + microchart

**Slices:** `StatTile` (hero Score / K/D) · `MiniStatGrid` (even grid, no orphan tiles) · `TierChip` / `TierScale` / `Pips` · `Sparkline`.

- **`StatTile` (recipe `stat-tile` L393):** `surface-1` + `border-1` + `rounded-md`; `label` role label (`text-muted`); value = `stat-xl` (Exo 2, tabular, 48px) `text-primary`; signed delta colored `win`/`loss` paired with `trending-up`/`trending-down` Lucide icon (never color-alone). Score and K/D are the two hero tiles side-by-side (naturally-equal — allowed).
- **`MiniStatGrid`:** even column grid (no orphan tiles — keep the tile count even). Metric priority Игры → Убийства → ТК → Смерти → K/D → Счёт (`.design/CLAUDE.md` L93, L175). Each value tabular mono.
- **Tiers (D-04) — population-derived, NEVER hardcoded cutoffs:** levels `ниже / норма / хорошо / отлично` computed from `SS_BASELINE` for the active period; `baseline` passed **explicitly** (never mutate a global). `TierChip`/`TierScale` show level name + entry threshold (e.g. `≥2.4 ХОРОШО`); `Pips` = the discrete level indicator. Score reaches `отлично` in the sample; K/D tops at `хорошо`. Tier color: tier-derived token, paired with the level word (never color-alone).
- **`Sparkline` (D-03) — custom, dependency-free:** DOM bars OR inline SVG filled with `var(--color-chart-*)` / tier tokens; NO recharts/visx/d3 (breaks CLS, imports a 2nd color system). `aria-hidden` on the chart; value exposed in an adjacent accessible label/tooltip (`figure` + hidden text summary). Honors `prefers-reduced-motion` (animate `transform`/`opacity` only). DOM-bars vs SVG is the planner's call.
- **States ×7:** tiles/chips enabled / hover / pressed (only if interactive — most are display-only, then hover/pressed n/a) / focused (if a link/button) / selected (active tier zone on `TierScale`) / disabled / loading (Skeleton at exact tile/chart dims).
- **Data-volume ×4:** few/many for `MiniStatGrid`; empty (no stats yet) shows reserved-height placeholder, not collapse. Sparkline: empty (flat baseline) / few points / many points / clamped range.
- **Click zone:** whole tile if the tile links to a detail; otherwise display-only.
- **Responsiveness:** hero tiles stack on mobile; mini-stat grid reflows column count by container width; Sparkline width fluid, height fixed (CLS = 0).

### KIT-04 — Data-trust components (A/C model ONLY — NOT "B")

**Slices:** `FreshnessPill` · `ProvenanceLine` · `KnownBadge` / `UnknownBadge` / `ConflictBadge` · `StaleBanner` / `OfflineBanner` / `ReconnectingBanner` · `InlineReviewRow`. (D-05; recipes DESIGN.md L406-439; tokens theme.css L135-158.)

- **`ProvenanceLine` = model A (recipe `provenance-line`):** `посчитано из N реплеев · <freshness> · Как считается` — always present under headline stats; `text-muted`, `2xs`, cyan "Как считается" link, `·` separator.
- **`FreshnessPill` = model C (recipe `badge-freshness`):** 4 states — up-to-date (`win`, `circle` filled dot) / stale (`warn`, `circle-dot`) / offline (`loss`, `wifi-off`) / reconnecting (`info`, `refresh-cw` spinning, respect `prefers-reduced-motion`). `rounded-full`. Consume the compound `--color-freshness-*` border token via inline `style` reading the custom property.
- **Known / Unknown / Conflict badges:** literal word + Lucide icon, amber for Unknown (`circle-help`) / Conflict (`triangle-alert`); Known = `surface-2` + `circle-check`. **NEVER color-alone, NEVER `0`/`—` for Unknown.** The only Unknown with backing today is `commander_side_stats.unknown_outcomes` (the КС surface) — per-player coverage panel "B" is NOT built (not in the data model).
- **`InlineReviewRow` (recipe `inline-review-row`):** quiet amber `на проверке` row + request link, rendered **inside** the SteamID list it describes — a workflow footnote, NEVER a filled banner, never pinned to the bottom of a stretched column.
- **Banners (`Stale`/`Offline`/`Reconnecting`):** **reserve their space** (CLS = 0), never color-alone (icon + text). They label cached/stale/offline/timeout data explicitly (`realtime.md`, `errors.md`).
- **States ×7:** badges/pills are display-only → enabled + (the 4 freshness variants count as content, not interaction). Focus applies only to the provenance link and the review-row request link. Loading = the pill in an indeterminate "reconnecting" state covers it; banners have no loading.
- **Click zone:** the "Как считается" link and the review-row request link are the only interactive zones (≥44px hit area on touch).
- **Data-volume:** N in the provenance line pluralizes (ICU in Phase 3; placeholder map here handles RU one/few/many forms manually).
- **Responsiveness:** provenance line wraps gracefully on mobile (stacks segments); banners full-container width, reserved height at every breakpoint.

### KIT-07 — Feedback primitives

**Slices:** `Skeleton` · `EmptyState` · `ErrorState` · `Toast` (visual primitive only) · `Badge` / `Pill` (incl. `badge-outcome-*` L295, `badge-status-*` L309).

- **`Skeleton`:** reserves the **exact final dimensions** (colgroup / header / row height for tables; tile dims for stats) → **CLS = 0**. Animate `opacity` only (shimmer), respect `prefers-reduced-motion` (drop to static). SSR-warm renders no skeleton; only a genuine async wait gets one.
- **`EmptyState`:** `h3` heading + `body` copy + an actionable next step + total-count where relevant (e.g. "clear filters to see all N"). Lucide icon at 24px. Reserved height.
- **`ErrorState`:** distinguishes **system** error (ref/debug id + contact path) from **user** error (sits by the field, names the fix — minimal this phase since catalog is read-only). Recovery action present, never a blank screen.
- **`Toast` (visual only, D-06/Deferred):** the visual primitive — surface, icon, message, optional action; `elevation.lg` shadow (it floats). NO trigger/portal/queue manager (Phase 3). States: the 4 semantic variants (success `win` / error `loss` / warn / info), each icon+label.
- **`Badge` / `Pill`:** `badge-outcome-win`/`-loss` (trending icon + W/L), `badge-status-pending`/`-approved`/`-rejected` (clock / badge-check / x-circle). `rounded-xs` for badges, `rounded-full` for pills only. Always icon + label.
- **States ×7:** `Toast`/`Badge`/`Pill` are mostly display; focus applies to a Toast action button (ring); disabled n/a. `Skeleton` is the loading state itself.
- **Scenario endings ×5:** these primitives ARE the vocabulary for success / error / loading / onboarding / empty across all surfaces — the catalog proves each renders correctly.
- **Responsiveness:** Toast pins bottom (mobile) / corner (desktop), reserved, no CLS; EmptyState/ErrorState center in their container at every breakpoint.

## Fixtures & Domain Consistency (QUAL-06)

Single shared module `packages/design/src/shared/uikit/_fixtures/` (D-06), imported by every stat/table/tier story:

From `gsd-ui-checker` + `solidstats-frontend-react-design-review` (2026-06-20). All non-blocking — fold into the plan, do not re-litigate the contract.

1. **[a11y] Full-row click → keyboard/SR row-navigation strategy is unspecified.** `TableRow`/`CompactRow` declare "whole row is the click target" but not which cell carries focus or how a screen reader traverses rows. Planner decides against `a11y.md` + WCAG 2.1.3: a native `<table>` with a focusable `<a>`/`<button>` in the player-name cell (Tab-navigable), or a grid-role table (`role="row"` + `aria-rowindex`). The contract gap is that neither is named.
2. **[states] Long-value overflow contract missing for text cells.** Spec-template §5 mandates "long values truncate+tooltip or wrap — never clip", but KIT-02 doesn't carry it for long nicknames / squad names. Planner adds: player-name cell `overflow: hidden; text-overflow: ellipsis` + `title`/Ark UI `Tooltip` on truncation; confirm the label-over-value stack works in `CompactRow` at the 360px floor.
3. **[ru-copy] Verify `FreshnessPill` "Данные устаревают" at 360px.** Grammatically fine but long for a pill in the narrowest column. Verify in the Ladle story; if it clips, consider "Устаревает" or graceful wrap (never mid-word). The spec already mandates the RU sanity-check — this is the tracking note.
