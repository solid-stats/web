<objective>
Paint the dark gunmetal base backdrop from the `--color-bg-0` token (and base text from `--color-text-primary`) via the theme generator, so the design system — not the browser's incidental dark canvas — guarantees the dark background.

Root cause (already verified live, do NOT re-investigate): `--color-bg-0` is defined in DESIGN.md and emitted into the `@theme` block, but Tailwind v4 tree-shakes it because its only consumer (the Ladle GlobalProvider's `bg-bg-0` utility) lives outside `@source "../src"`. html/body/#ladle-root all compute transparent; the dark you see is the browser canvas.

Fix: emit an `@layer base` block (an `html` rule reading `var(--color-bg-0)` / `var(--color-text-primary)`) from the generator, AFTER the `@theme` block. Referencing the vars in real CSS both (a) forces Tailwind v4 to retain the tokens (kills tree-shaking) and (b) paints the base via a real rule independent of utility scanning.

Purpose: The dark-only design-system foundation must own its base backdrop from tokens, surviving regeneration.
Output: Edited `scripts/gen-theme.mjs` + regenerated `packages/design/src/styles/theme.css`, committed together.
</objective>
