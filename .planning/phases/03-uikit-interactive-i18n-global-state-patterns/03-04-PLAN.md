## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user file selection → FileUpload client validation | THE genuine threat surface in this no-app phase: a user-chosen file crosses into the client. Validation here (type/size/SVG) is defense-in-depth UX; the authoritative gate is server-2 in v1.0. No network/upload actually happens in v0.1 (presentational Ladle). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04-01 | Tampering / Elevation | SVG upload (stored-XSS vector) | high | mitigate | Default accept = png/jpeg/webp ONLY; `image/svg+xml` excluded and asserted by fileUpload.test.ts; rejection state names the reason. Client-side defense-in-depth (real gate server-2 v1.0). |
| T-03-04-02 | Denial of service | object-URL memory leak from un-revoked previews | medium | mitigate (Ark-owned) | Ark's `ItemPreviewImage` creates AND revokes each preview blob URL in its own effect cleanup (`createFileUrl` → `revokeObjectURL` on unmount / row removal); the per-file URL is never exposed to the slice, so the lifecycle is owned entirely by Ark — no slice-level tracker. DOM revoke is covered by the Playwright pass, not a Vitest unit (the prior pure `createPreviewUrlTracker` was dead code asserting nothing about the component and was removed). |
| T-03-04-03 | Denial of service | oversize file | low | mitigate | maxSize client validation with a why+fix rejection state (UX only; server-2 enforces the real limit v1.0). |
| T-03-SC | Tampering | npm installs | n/a (no installs this plan) | mitigate | Deps gated by the Plan 03-01 blocking-human checkpoint. |
